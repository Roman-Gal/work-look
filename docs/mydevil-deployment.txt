   disabled. The website cannot redirect updates from the working local bots.

Bot/API activation is a separate authorized step:
 - Choose/approve the actual external service account and key, and approve secret/data
   transfer. Populate private server .env files; never commit or expose credentials.
 - Explicitly decide whether to migrate current databases or start clean. Before an
   actual migration stop only the identified local bot processes, then take final
   SQLite backup-API snapshots; a lone .sqlite copy while WAL is active is insufficient.
 - Configure the matching ingress secrets/ports in WorkLook, start one bot worker
   per database, and register webhooks with drop_pending_updates=false.
 - Verify getMe/getWebhookInfo and health endpoints, without unsolicited test messages.
 - Never run the old planner reminder worker concurrently with the migrated instance.
 - Temporary deployment SSH access was removed after the checks. A fresh key-only
   connection was denied, then local private/public key files were deleted.
   The owner's existing interactive SSH session/password were not changed.
