Deployment requirements:
 - WorkLook: PHP 8.4 CLI/web, Composer install --no-dev, prod env, PostgreSQL or SQLite,
   migrations, compiled AssetMapper assets, public/ as the only document root, HTTPS,
   private runtime data and a bounded Messenger worker. Create/preserve a private login.
 - Planner: Node 22.22+ or a compatible newer version with node:sqlite. Native HTTP
   server and persistent timer/queue worker must stay running even without web traffic.
   Use a reserved loopback port and HTTPS proxy, a single supervised process, private
   .env and SQLite data. Passenger idle shutdown alone is unsuitable for reminder timing.
 - Ukrainizator: Python 3.11+, FastAPI/Uvicorn, SQLite, language detector and a working
   translation endpoint. The current local endpoint is LibreTranslate at 127.0.0.1:5000.
   Native FreeBSD compatibility must be checked. CTranslate2 binary wheels list Linux,
   macOS and Windows; a ready FreeBSD install cannot be assumed. No alternate third-party
   translation service will receive chat messages without choosing that provider first.

Cutover:
 - Inventory the account and back up any existing server configuration first.
 - Build isolated directories and dependencies; transfer secrets only over authenticated
   SSH/SFTP, never Git. Preserve the configured chat restrictions and owner settings.
 - Confirm private app access, SSL, proxy routing, health endpoints and secret rejection.
 - Stop only the identified local bot processes, take consistent final SQLite backups
   through SQLite's backup API (not a lone .sqlite copy while WAL is active), transfer,
   then start the remote processes and update webhooks with drop_pending_updates=false.
 - Do not run old reminder workers in parallel with the new planner.
 - Verify getMe/getWebhookInfo and /health; avoid unsolicited test messages to real chats.
 - Keep rollback backups. Preserve other cron entries/sites; add only managed entries.
 - Record final URLs, exact revisions, runtime paths and restart/rollback commands here.
