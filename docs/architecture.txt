WorkLook implementation map
Originally recorded 2026-11-20; current deployment details: mydevil-deployment.txt.

Default flow (operator-assisted batches, 2026-11-25)
Browser /resume upload -> private PDF/text + privacy notice version in DB
 -> /requests/new -> LocalWorkRequest snapshot (one pending request per account)
 -> operator download -> optional Codex CLI or manual desktop-app processing
 -> reviewed JSON upload -> owner result page + PDF rendering + email notification.
Machine transfer uses a dedicated token hash; no website API model call or trial
reservation occurs in this flow. See local-processing.txt for boundaries.

Legacy API flow (LOCAL_BATCH_ENABLED=0)
Browser POST / (CSRF + authenticated User)
 -> DashboardController -> SearchAllowance + SearchLauncher
 -> atomic allowance reservation, AgentRun(profile snapshot) and Doctrine Messenger dispatch
 -> StartAgentRun(runId,userId) -> StartAgentRunHandler(owner check)
 -> AgentRunner(run lock + database claim)
 -> OpenAiClient Responses -> function_call -> ToolExecutor -> function_call_output
 -> repeat until final message, cancellation, limit or failure.
A Turbo Frame polls GET /runs/{id}; authentication and ownership remain server-side.
Turbo Drive is disabled so full navigations refresh the document's CSP nonce.

The agent has exactly six tools:
 get_my_profile(): snapshot facts, preferences, headline, sources and score threshold.
 get_search_knowledge(query,source): reviewed shared guidance + this owner's saved
                                  prompts, restricted to allowed sources; four bounded results.
 search_jobs(source,keywords,page): allowlist and budget; up to 10 jobs per request.
 get_job_details(job_id): only jobs discovered by this run.
 save_job_match(job_id,score,reasons,gaps): after reading details; no expired jobs.
 prepare_cv(job_id,fact_ids): saved match at/above threshold, full description,
                             known snapshot fact IDs, no rewriting of their text.
user_id is never a model argument. The backend enforces limits. Instructions to
review up to 4 jobs / prepare up to 2 CVs are model guidance, not separate server
quotas; the hard bound is the total tool budget.

Storage
 User -> Profile (one-to-one).
 User -> AgentRun: request, model/tool counters, events, immutable profile snapshot.
 User.freeSearchRunId: null for an unused free search; the reserved/consumed run otherwise.
 Job: shared public data, unique(source,external_id).
 AgentRun + Job -> JobMatch: unique(run_id,job_id), jobSnapshot frozen at creation.
 JobMatch: selectedFactIds, score/reasons/gaps and a manually selected status.
 messenger_messages: async/failed queues; the transport does not send CVs to employers.
AgentRun statuses: queued/running/completed/failed/cancelled/limited.
JobMatch statuses: New/Reviewed/Applied/Skipped. Applied is a user's label only.
A detailed application log with dates and status history is not implemented.

 cache, remote/JS/PHP disabled, chroot restricted to var and the font directory.
 assets/styles/fonts.css: four font faces; assets/fonts/zakon/NOTICE.txt: provenance.
 src/Message/ and src/MessageHandler/: background entry into the runner.
 src/Command/: private user creation, source diagnostics and explicit test-data reset.
 src/EventSubscriber/: CSP nonces, the exact Turbo CSS hash and security headers.
 LocaleSubscriber (priority 20): validates uk/pl/en from worklook_locale.
 LanguageController: public CSRF-protected POST, HttpOnly/SameSite=Lax cookie,
 secure over HTTPS, redirects only to known UI paths. Polling shares this cookie.
 translations/messages.{uk,pl,en}.yaml: UI, forms and progress; app.request.locale
 controls HTML lang and PDF headings. CV facts do not pass through Translator.
 profileSnapshot.ui_locale fixes the language of new AI explanations without a migration.
 templates/ and assets/: Twig/UX, without a CDN, separate SPA or Node build.
 tests/: disposable SQLite integration/unit fixtures; external calls are mocked.
 src/Controller/AdminController.php: singleton-owner statistics and user management.
 src/EventSubscriber/ActivitySubscriber.php and src/Service/ActivityRecorder.php:
 private website activity and transactional administrator audit; excludes bot gateways.
 src/Service/IpLocation.php: local MMDB lookup; see administration.txt for retention.
 src/Controller/ResumeController.php: private text-PDF draft and manual prompt/JSON flow.
 src/Service/ResumeTextExtractor.php and tools/extract-resume.php: bounded CLI parsing,
 no OCR. ResumeProfilePreparation validates source excerpts before profile preview.
 src/Controller/KnowledgeController.php and src/Service/KnowledgeBase.php: reviewed
 shared KB and owner-scoped prompts. See resume-and-knowledge.txt for boundaries.
 tools/router.php: local PHP development server only.

Current normalized adapter record (not the richer proposed DTO)
 source, external_id, title, company, url, description,
 locations:string[], salaries:{min,max,currency,period,contract_type,gross_net,source_path}[],
 skills:string[], work_mode, completeness, expires_at.
Search result: jobs[], next_page:int|null, coverage:partial|window.
SOLID: public-api/offers/IT, search.searchTerm, pages 0..2, pageSize 10.
DOU: vacancies/feeds/?search=; Djinni: jobs/rss/?keywords=; both page 0 only.
GET cache: 3600s, keyed by endpoint/query; 3 MB cap, no redirects/retries.
Source diagnostics do not write jobs to the database. There is no arbitrary HTTP
tool, HTML parser, scraper or browser fallback.

Salary normalization preserves currency/period and never treats B2B as UoP.
RSS company/location/salary/work_mode remain unknown even when a title contains
suggestive words. Absence from the latest RSS window does not mean deletion.
Raw payloads are not stored in the current DB; normalized data and contentHash are.
Research GET evidence is stored separately in research/evidence/.
