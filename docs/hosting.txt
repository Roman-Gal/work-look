Unlimited websites do not imply unlimited CPU or RAM.

2. Projects in different languages

Each project has its own directory, dependencies, configuration, secrets, logs and
startup method. Web projects may use separate subdomains. Symfony uses Composer/vendor;
Python uses a separate virtualenv; Node uses its own package lock/node_modules and
runtime version. A virtualenv isolates dependencies, not OS-level access.
Check native extensions/binaries against the host's actual platform.

https://pomoc.mydevil.net/Strona_WWW/
https://pomoc.mydevil.net/Python/
https://pomoc.mydevil.net/Node.js/
https://pomoc.mydevil.net/PHP/

Several small bots and Symfony can coexist, but disk space alone does not establish
capacity. Measure combined RAM, processes, CPU, concurrency and logs. Bound heavy
PDF/AI work. WorkLook calls external LLM APIs rather than hosting a large local model.

3. Domains

A purchased domain is optional initially: the provider supplies login.usermd.net.
Later one domain can serve multiple subdomains, for example:
 jobs.example.com: WorkLook
 bots.example.com: bot webhooks/panels
 portfolio.example.com: an optional portfolio
These are examples, not registered/selected addresses. A separate paid domain is
not required for each project or bot. Configure DNS, the hosting website and HTTPS.
https://pomoc.mydevil.net/SSL/

Telegram long polling (getUpdates) makes outgoing requests and needs no public
inbound URL, but does need a persistent process and restart strategy.
Webhooks need a reachable HTTPS endpoint; the provider's hostname is sufficient.
Different bots can use different URL paths on one host. Do not enable polling and
a webhook simultaneously for the same bot.
https://core.telegram.org/bots/api#getting-updates

4. Containers and processes

Docker is not required for PHP/Python/Node coexistence. MD2 deployment is native,
using SSH, installed runtimes and provider tools. Docker daemon/Compose support was
not confirmed, so production does not depend on it.
Docker Compose is optional locally; container hosting would need a platform with
explicit support, such as a suitable Linux VPS.
https://docs.docker.com/engine/install/

Bots and Messenger workers run independently of HTTP requests. Provide restart,
startup after reboot and RAM/concurrency limits. screen/nohup alone is not a restart
supervisor. Use cron with a lock to prevent duplicate workers.
https://pomoc.mydevil.net/Cron/
Passenger's web-app idle/restart behavior does not supervise a polling bot.
Validate long-running versus bounded cron workers on the account.

5. WorkLook deployment

Symfony UX/Twig lives in the same application. The only web root is public/;
private CVs remain outside it. Use provider PostgreSQL, Doctrine Messenger and a
managed CLI worker. DATABASE_URL and runtime paths are environment configuration;
Docker service names such as postgres are not fixed production hosts.
https://pomoc.mydevil.net/PostgreSQL/
Verify PDF binaries/libraries on FreeBSD rather than assuming Linux Chromium works.
Job-source GET research: research/00-README.txt.

Historical first deployment, 2026-11-20: an isolated SQLite demo was launched, bot
code/dependencies installed with placeholder credentials, and bot processes left
inactive while private transfers were withheld. DeepL was chosen instead of local
LibreTranslate and initially tested using mock HTTP.
That initial state was superseded: all three apps now use PostgreSQL, bot credentials
were transferred with permission, and both bots are active. WorkLook's final quota
