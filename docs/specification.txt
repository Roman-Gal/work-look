# Специфікація Агента 2: Пошуковик роботи (Польща) та Адаптер CV

Збережено: 2026-11-20.
Статус: реалізацію дозволено користувачем; локальний MVP у корені цього репозиторію.
Пізніші рішення користувача мають пріоритет над початковим текстом нижче:
- Symfony 7.4 LTS + Symfony UX/Twig, без Angular.
- Кнопка вручну запускає AI-агента, який обирає пошукові запити та викликає API/RSS tools.
- Автономний scraper і автоматичний розклад пошуку не потрібні на цьому етапі.
- Локально SQLite; майбутній хост MyDevil MD2, план PostgreSQL і нативні workers.
- Реалізація, запуск та обмеження: README.txt, docs/architecture.txt.
Нижче збережено початкову специфікацію як цільовий розвиток, не перелік готових функцій.

## 1. Мета та архітектура проєкту

Приватний сервіс / агентський пайплайн (з перспективою масштабування в мультикористувацький пет-проєкт/SaaS), який регулярно збирає вакансії на польському ринку праці, фільтрує їх під вимоги користувача, адаптує резюме (CV) під конкретну вакансію без вигадування фактів, готує пакет матеріалів і формує структурований звіт.

## 2. Рекомендована архітектура системи

Розділяємо систему на незалежні модулі/воркери через чергу задач і реляційну БД:

- **Ingestion Worker (Збір даних):** адаптери під різні джерела вакансій (`JustJoinIT`, `NoFluffJobs`, `Pracuj.pl`, `Bulldogjob`, `The Protocol` тощо). Працює за розкладом (cron / scheduler).
- **Storage (PostgreSQL):**
  - `users` / `user_profiles` (базове CV у структурованому вигляді JSON/Markdown, бажана зарплата, формат роботи, локація/адреса старту, мови, критерії фільтрації).
  - `job_sources` та `jobs` (унікальний ключ `source + external_id` або `url`, raw payload, нормалізовані поля, статус обробки).
  - `job_matches` (оцінка релевантності, пояснення, відстань/час доїзду, посилання на згенероване CV).
  - `applications_log` (звітність: що підготовлено/надіслано, яка версія CV, статус).
- **Matching & Scoring Agent:** оцінює відповідність вакансії профілю користувача та відсіює нерелевантні позиції.
- **CV Adaptation & Renderer:** створює цільову версію CV під опис вакансії та рендерить у готовий файл (наприклад, PDF через HTML/CSS шаблони або Typst).
- **Reporting & Notification Module:** формує звіти (таблиця/дашборд + сповіщення, наприклад у Telegram або веб-інтерфейсі) для ручної перевірки та відправки користувачем.

## 3. Підходи до джерел вакансій (API / ендпоінти vs парсинг)

На польському ринку праці підходи відрізняються залежно від порталу та його актуальної frontend/backend-архітектури (оскільки портали періодично оновлюють API та антибот-захист, кожен адаптер варто виносити в окремий модуль із чітким контрактом):

1. **JSON / REST / GraphQL ендпоінти SPA-застосунків:**
   - Багато сучасних IT-бордів у Польщі (зокрема `JustJoinIT`, `NoFluffJobs` та нішеві дошки) підвантажують списки вакансій і деталі через внутрішні/публічні JSON API або структуровані фіди.
   - *Перевага:* швидше, легше й стабільніше, ніж парсити HTML.
   - *Вимога до агента/адаптера:* коректні заголовки запитів, повага до rate limits, обробка пагінації та падінь схеми відповіді (fallback на headless browser).
2. **HTML / Headless Browser (`Playwright`):**
   - Використовується для порталів з рендерингом на клієнті, складними фільтрами або захистом від простих HTTP-клієнтів (наприклад, частини сторінок `Pracuj.pl` чи агрегаторів).
3. **Робота з геолокацією / відстанню до роботи:**
   - Для офісних або гібридних вакансій у Польщі корисно витягувати місто/район або координати і рахувати відстань/час у дорозі від базової точки користувача (через геокодинг + routing API, наприклад OpenRouteService / Google Maps), додаючи це поле у звіт.

## 4. Логіка AI-агентів (Scoring + CV Tailoring)

1. **Агент оцінки вакансії (Matcher):**
   - Вхід: нормалізована вакансія + профіль користувача.
   - Вихід (JSON schema): `match_score` (0–100), `reasons_for_fit`, `missing_skills_or_red_flags`, `salary_info`, `work_mode`, `location`.
   - Вакансії нижче порогу релевантності не витрачають токени на генерацію CV.
2. **Агент адаптації CV (CV Tailorer) — жорсткі анти-галюцинаційні правила:**
   - Вхід: структуроване «канонічне CV» користувача + текст вакансії.
   - Дозволено: переставляти акценти, переформульовувати буліти досвіду під термінологію вакансії, підсвічувати релевантні проєкти/навички, адаптувати мову CV (наприклад, польська або англійська — залежно від вимог вакансії).
   - **Категорично заборонено:** вигадувати досвід, компанії, ролі, сертифікати, роки стажу або навички, яких немає в канонічному CV користувача. Усі факти мають мати прив’язку до джерела в базовому профілі.

## 5. Звітність та майбутній перехід у Pet-Project / SaaS

- **Формат звіту по кожній підібраній вакансії:**
  - Назва посади та компанія.
  - Пряме посилання на вакансію.
  - Зарплатна вилка та тип контракту (якщо вказано, напр. `UoP`, `B2B`).
  - Локація / формат (`remote`, `hybrid`, `office`) + відстань/час доїзду від заданої точки.
  - Прикріплений/згенерований файл CV (та короткий changelog змін у CV).
  - Статус (`New`, `Reviewed`, `Applied`, `Skipped`).
- **Готовність до масштабування (ізоляція даних користувачів):**
  - З самого початку проектувати БД і пайплайни з `user_id` / `tenant_id`, щоб завантаження CV, налаштування фільтрів і черги задач легко масштабувалися на кількох користувачів без переписування ядра.
