Adapter contract and first implementation plan
Original target specification, 2026-11-20.
The Symfony MVP is implemented; its simpler actual contract is ../architecture.txt.
Commands: ../../README.md. Not every DTO/field/module below is implemented.
Adapters are tools of a user-triggered AI agent, not an autonomous scraper.
Current storage is shared MyDevil PostgreSQL. Summary-only RSS jobs cannot generate CVs.

1. First-stage boundaries

Input: allowlisted HTTP JSON API or XML RSS.
Output: normalized PostgreSQL vacancies linked to the original source.
Initial implementation: one Console command/source/page, followed by queue integration.
No automatic application or CV upload to an employer.
Cleaning HTML embedded in RSS/JSON fields does not authorize scraping website pages.

2. Proposed contract

JobSourceAdapter:
  capabilities(): SourceCapabilities
  fetchPage(SourceQuery query, ?OpaqueCursor cursor): JobPage
  fetchDetails(JobReference job): JobDetailsResult

SourceCapabilities:
  source_id, format=json|rss, access=public|internal|partner,
  pagination=page|cursor|none|unverified,
  details=inline|separate|summary_only|unverified,
  supports_server_filters, configured_poll_interval, configured_request_budget.

JobPage:
  items[], next_cursor|null, fetched_at, upstream_total|null,
  coverage=complete_snapshot|window|partial|unknown,
  warnings[], source_response_hash.

JobDetailsResult:
  state=available|not_supported|forbidden|not_found|retry_later|schema_changed,
  job|null, warnings[].

OpaqueCursor keeps platform paging models separate: SOLID uses pageIndex,
DOU/Djinni use a window without a next cursor, and JJIT paging is unverified.
Keep adapter filters separate from local user criteria. Fetch a public vacancy
once for multiple users; calculate matches separately.

3. Normalized vacancy

source, external_id, source_url, apply_url?, first_seen_at, last_seen_at,
published_at?, updated_at?, expires_at?, source_active?, content_hash,
title, company_name?, description_text?, description_html_sanitized?,
content_completeness=full|summary|unknown, missing_fields[],
locations[] { country_code?, city?, address?, latitude?, longitude? },
work_mode=remote|hybrid|office|field|mixed|unknown,
remote_eligible_countries[], remote_eligibility=confirmed|restricted|unknown,
skills[] { name, required?, source_path }, seniority?, languages[],
salary_offers[] { min?, max?, currency?, period?, contract_type?, gross_net?,
                  is_estimate, original_text?, source_path },
raw_payload_reference?, adapter_version, normalization_warnings[].

Missing values are null/unknown, not zero or assumptions. Do not infer PLN/UAH from
a site's name, compare UoP gross to B2B net without a calculation model, or silently
multiply hourly pay by 168. Preserve original period/currency/contract beside
derived estimates. Missing salary can be unknown rather than automatic rejection,
depending on the profile. AI-extracted job facts need source_path/text evidence.

4. HTTP reliability

Allowlist domains/routes; build query parameters with the HTTP client, not user URLs.
External keys belong only in backend secrets, never Twig HTML/browser assets/Git.
Proposed initial application caps, not provider guarantees: one concurrent request
per source, 20–50 jobs/page where supported, bounded pages/time per run.
Original refresh proposal: SOLID/DOU/Djinni hourly; Remotive at most 4 requests/day.
Current search is manual; per-source access/cache policies still apply.

304: retain the previous payload; use conditional GET if supported.
429: honor Retry-After or bounded backoff with jitter.
5xx/timeout: bounded retries in a future adapter policy.
401/403: stop the source and record access_required.
405: wrong method; 404/410 details: unavailable rather than a full ingestion crash.
200 with HTML, error envelope or broken schema: schema_changed, not successful emptiness.
Do not bypass challenges/403 using rotating proxies. The research utility never retries.

Detect repeated pages through hashes, IDs and cursor progress. Repetition, oversized
bodies or exhausted budgets yield partial + warning, not complete.
Partial runs/RSS windows cannot mass-expire absent jobs.
RSS guid may be a URL; keep canonical-source-URL fallback.
Within-source identity: source + external_id. Cross-source deduplication needs a
separate company/role/location/link fingerprint while preserving source references.

5. Storage and ownership

Only public jobs/job_sources are shared. Profiles, canonical CVs, matches, CV
versions, application statuses and private files belong to user_id/tenant_id.
Queue messages carry scope/IDs; check ownership after loading entities.
Freeze the profile version for matching/preparation; never attach another user's
CV or an unrelated old version. UUID unpredictability alone is not file authorization.
Raw payloads need limited retention and minimization of unnecessary contact details.

6. AI and CVs

Apply deterministic filters before scoring and the configurable CV threshold.
Keep summary-only jobs, such as the robota sample, as NeedsDetails; postpone CVs.
Even inline descriptions need sufficient requirements for meaningful preparation.
Vacancy text is untrusted data and cannot instruct the agent to change rules,
read secrets or invent candidate skills.
Each CV claim references fact_id in a specific canonical-profile version.
The proposed future design allows translation/rewriting with no new facts; current
code selects original facts only. Validate IDs before rendering and reject unsupported
claims rather than inventing fixes. Preserve changelog and job/profile/prompt/model
versions for reproducibility.

7. Original MVP sequence

1) Console + HttpClient: one SOLID page -> normalized DTO -> PostgreSQL.
2) Check deduplication, distinct pageIndex=0/1 results, real filters and optional/null fields.
3) DOU/Djinni RSS: embedded HTML cleaning, guid fallback, window coverage, missing details.
4) Messenger: budgets, retries, run log and explicit source enablement.
5) Twig/UX dashboard, filters, profiles and New/Reviewed/Applied/Skipped statuses.
   Applied is set manually and does not submit an application.
6) Scoring -> provenance-checked CV facts -> renderer -> preview/download/manual review.
7) Local reverse proxy/ngrok preview, then hosting.

Useful contract tests: anonymized fixtures, repeated pages, 429/403/bad JSON,
tenant isolation and rejection of unknown CV fact IDs.
Live endpoints belong in manual smoke checks, not every CI run.
