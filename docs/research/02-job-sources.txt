Job sources: Poland, Ukraine and supplementary APIs
Research observations from 2026-11-20. These are dated findings, not live guarantees.
Current adapters: ../../README.md and ../architecture.txt.

Status definitions
PUBLIC: documented public API or an RSS feed published by the source itself.
INTERNAL: HTTP endpoint accessible, but a supported public contract is unconfirmed.
PARTIAL: only part of list -> detail verified. FAILED: the particular check failed.
UNKNOWN: no suitable documented job-read API confirmed during this research.
UNKNOWN does not prove that no API exists. Employer job-posting APIs are not
automatically APIs for searching/reading vacancies.

1.1. SOLID.Jobs: recommended Polish starting point

GET https://solid.jobs/public-api/offers/IT?campaign=jobfind-local-research&pageSize=1&pageIndex=0
No key. campaign identifies the integration; it is not a secret.
Observed: 200 JSON, jobs[1], totalCount=1414 at the time.
pageIndex=1 returned a different jobOfferKey. Paging is zero-based.
Fields: jobs[].jobOfferKey, title, company, url, description, salary, secondarySalary?,
locations, isRemote, isHybrid, skills, languages, experienceLevel,
validFrom/validTo/updatedAt. One sample does not prove every optional field is present.

Documented query parameters: pageIndex, pageSize, sortActive, sortDirection,
search.cities, search.searchTerm, search.experiences, search.minimumSalary.
Documented pageSize maximum: 500; the initial research proposal was 20–50.
search.searchTerm=PHP returned 200 and one record; search accuracy/coverage still
needs a separate sample. Version header: X-Api-Version: 1.0.
Published limit when checked: 300 requests/minute/IP; cache for up to one hour.
The initial refresh proposal was hourly; current app searches are user-triggered.
https://solid.jobs/api-ofert-pracy
https://github.com/solid-company/solid-jobs-client
Evidence: solidjobs.json, solidjobs-page1.json, solidjobs-php.json under evidence/.

RSS alternative:
GET https://solid.jobs/rss/job-offers/subcategory/PHP
Observed 200 RSS. Published feeds: https://solid.jobs/about/rss
Do not enable API/RSS as independent streams without deduplication.

1.2. JustJoinIT: experimental INTERNAL integration

GET https://justjoin.it/api/candidate-api/offers?page=1&perPage=1
GET https://justjoin.it/api/candidate-api/offers/{slug}
Both returned 200 JSON without authentication. Read slugs from the list; do not
construct them from titles.
List: data[], meta.from, meta.totalItems, meta.prev/next with cursor and itemsCount.
Both perPage=1 and limit=1 returned 10 records; neither parameter is verified.
meta.totalItems=10000 is an observed value, not proof of full board coverage.
Next-cursor transmission and search filters remain unresolved. A blind page++
loop may repeat the same page.

List identity: guid; detail identity: id. Preserve slug and establish ID mapping.
List fields: title, companyName, workplaceType, experienceLevel, requiredSkills,
employmentTypes, locations, publishedAt/expiredAt.
Detail: body, url, canonicalSlug, isActive.
employmentTypes contains currency, unit, gross, from/to and fromPerUnit/toPerUnit;
do not confuse converted salaries or periods with separate contracts.
Evidence: justjoin.json, justjoin-limit.json, justjoin-detail.json.
https://justjoin.it/
https://justjoin.it/terms-and-privacy-policies

A separate GET confirmed Disallow: /api/ in https://justjoin.it/robots.txt
Do not treat this internal route as an open collection feed. Regular experimental
ingestion remains disabled until supported access is clarified.

1.3. NoFluffJobs: distinguish list, search and details

GET https://nofluffjobs.com/api/posting
Observed 200 application/json, but the body exceeded even the 20 MB research cap
(curl exit 63). JSON was not validated and no complete shape was recorded.
Do not load this entire feed on every UI click.

GET https://nofluffjobs.com/api/search/posting
Observed 405 with Allow: POST. This is not working GET search.
POST search may be semantically read-only, but its payload/parameters were not
tested. Do not invent a POST contract in a production adapter.

GET https://nofluffjobs.com/api/posting/{slug}
Checked slug: software-engineer-big-data-adform-warszawa-1.
Observed 200 JSON. Fields: title, company.name, details.description,
requirements.musts/nices, requirements.description, specs.dailyTasks,
essentials.originalSalary, location.places[].geoLocation, expiresAt, status,
postingUrl/defaultUrl. Full descriptions may span several sections.
Details are technically readable; an end-to-end search integration is not ready.
Evidence: nofluff-list.json, nofluff-search-get.json, nofluff-detail.json.
https://nofluffjobs.com/
https://nofluffjobs.com/robots.txt also listed Disallow: /api/
MVP status: experimental and disabled by default.

2. Ukrainian platforms

2.1. DOU: PUBLIC RSS, first Ukrainian adapter

GET https://jobs.dou.ua/vacancies/feeds/?category=PHP
Observed 200 application/rss+xml with 25 items.
Item fields: title, link, guid, pubDate, description (an embedded HTML fragment).
The feed is linked from https://jobs.dou.ua/vacancies/
category=PHP was tested; derive other filter combinations from the site's published
RSS link after selecting filters rather than guessing parameters.
Separate structured salary/company/work-mode JSON was not confirmed. Preserve
unknown/null, or extract only with explicit evidence from the provided description.
A nonempty description does not establish full requirements for every vacancy.
RSS is a recent window, not a complete archive or proof old jobs are still active.
Observed Cache-Control: max-age=600. Initial refresh proposal: hourly.
Evidence: dou.json.

2.2. Djinni: PUBLIC RSS, job-search JSON API unconfirmed

GET https://djinni.co/jobs/rss/?primary_keyword=PHP
Observed 200 application/rss+xml with 23 items.
Fields: title, link, guid, pubDate, description, repeated category.
Published feed link: https://djinni.co/jobs/
This path needs no HTML scraper or JSON API. Do not assume all profile filters or
login-only vacancies appear in the feed. Remote does not prove permission to work
from Poland; inspect country/region restrictions. Salary, contract and language
may be unstructured or missing.
Initial refresh proposal: hourly; no exact public API rate limit established.
Evidence: djinni.json.

2.3. robota.ua: INTERNAL, PARTIAL

GET https://api.robota.ua/vacancy/search?keyWords=php&count=1&page=0
Observed 200 JSON: documents[1], count=1, total=33.
Envelope: documents[], total, start, count, errorMessage.
Fields: id, name, companyName, notebookId, salaryFrom/To, salaryComment, cityName,
latitude/longitude, shortDescription, date. Currency and gross/net were not
confirmed in the sample. Only page=0/count=1 were checked; paging/filter semantics
still need validation.

GET https://api.robota.ua/vacancy?id=11386804
Observed 403 in the research environment. No full description obtained and no
bypass attempted. Do not prepare a CV from shortDescription alone.
Until detail access is resolved, treat records as discovery summaries with
content_completeness=summary and NeedsDetails.
Evidence: robota.json, robota-detail.json. https://robota.ua/
Supported public documentation for this read endpoint was not found.

2.4. Work.ua: important source, API-first access UNKNOWN

No documented external API for searching all vacancies was confirmed.
Do not invent /api/jobs or developers.work.ua routes.
Failed API-subdomain lookups do not disprove partner integrations.
Ask through official cooperation channels about feeds/job-search access; manual
vacancy-text import is a possible interim path without scraping.
No messages were sent to the platform.
https://www.work.ua/about-us/
https://www.work.ua/about-us/contact/

3. Supplementary official APIs for Poland/remote coverage

These do not replace every named board. ATS feeds cover selected employers, not
the whole labor market.

Adzuna: documented GET requiring app_id + app_key. No keys available; not tested.
https://api.adzuna.com/v1/api/jobs/{country}/search/{page}
Confirm pl availability/account terms before claiming Polish coverage.
Descriptions may be summaries and salaries estimates; distinguish estimates from
an employer's advertised range.
https://developer.adzuna.com/overview
https://developer.adzuna.com/docs/search

Jooble: official keyed API, key required separately; not tested.
Verify current request method/body against official documentation before coding.
Do not assume an aggregator provides complete coverage of unavailable direct APIs.
https://jooble.org/api/about

Greenhouse:
GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs
Checked stripe: 200 JSON jobs[], no read key.
content=true is documented, but the trial response exceeded 5 MB, so successful
saved evidence uses the list without descriptions.
GET .../jobs/{id} exists in the docs but was not separately tested.
https://developers.greenhouse.io/job-board.html
Evidence: greenhouse.json.

Lever:
GET https://api.lever.co/v0/postings/{site}?mode=json&limit=1
Checked spotify: 200, one-element array.
Fields: id, text, categories, descriptionPlain, lists, hostedUrl/applyUrl,
workplaceType. Select US/EU hosting according to the board.
This is an employer feed, not global search.
https://github.com/lever/postings-api
Evidence: lever.json.

Ashby:
GET https://api.ashbyhq.com/posting-api/job-board/{board}?includeCompensation=true
Checked ashby: 200, jobs[79].
Fields: id, title, jobUrl, descriptionPlain, location/secondaryLocations, isRemote,
workplaceType, compensation?, publishedAt.
Do not display unlisted jobs. Derive hiring countries/currency from data, not ATS domains.
https://developers.ashbyhq.com/docs/public-job-posting-api
Evidence: ashby.json.

Remotive:
GET https://remotive.com/api/remote-jobs?search=php&limit=1
Observed 200 JSON jobs[15] despite limit=1; these filters/limit were not confirmed.
Fields: id, url, title, company_name, candidate_required_location, salary, description.
Salary is free text. Data is delayed; documentation recommended at most 4 calls/day.
Attribute Remotive; review restrictions on registration-gated display before SaaS use.
https://github.com/remotive-com/remote-jobs-api
Evidence: remotive.json.

Arbeitnow:
GET https://www.arbeitnow.com/api/job-board-api?page=1
Observed 200 JSON data[300], links.next pointing to page=2; page 2 was not fetched.
Fields: slug, company_name, title, description, remote, location, url, created_at.
Supplementary European coverage focused on Germany, not a primary Polish board.
Filter country/remote eligibility; remote=true alone does not establish eligibility.
https://www.arbeitnow.com/blog/job-board-api
Evidence: arbeitnow.json.

4. Integration order

First: SOLID.Jobs JSON -> DOU RSS -> Djinni RSS.
Next: selected employers through Greenhouse/Lever/Ashby; keyed Adzuna/Jooble if needed.
Experimental: JJIT paging/supported access; NoFluffJobs search payload; robota details.
Pracuj/theprotocol/Bulldogjob/RocketJobs/Work.ua follow confirmed feed/API access.
This provides real vacancies without scrapers or invented API contracts.
